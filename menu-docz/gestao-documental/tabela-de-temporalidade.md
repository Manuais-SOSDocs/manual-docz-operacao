# Tabela de temporalidade

Esta tela permite a gestão da **Tabela de Temporalidade Documental**, onde são definidos os prazos de guarda dos documentos, tanto na fase corrente quanto na fase intermediária, bem como a destinação final (eliminação ou guarda permanente). Apresenta uma lista com as classificações documentais e seus respectivos prazos e destinações.

A funcionalidade **Exportar Dados** permite gerar arquivos da Tabela de Temporalidade para consulta, auditoria, backup ou compartilhamento das estruturas classificatórias cadastradas no sistema.

Além da exportação completa da tabela, o DocZ também permite exportar apenas uma parte da estrutura hierárquica, facilitando a extração de informações específicas sem a necessidade de exportar toda a base de classificação.

#### Como exportar a Tabela de Temporalidade

1. Acesse **Gestão Documental > Tabela de Temporalidade**.
2. Clique no botão **Exportar Dados**.
3. Selecione uma das opções disponíveis:
   * **Exportação Completa**
   * **Exportação Hierárquica**
4. Configure os filtros desejados.
5. Clique em **Exportar**.

O sistema gerará o arquivo seguindo o padrão de exportação utilizado pelo DocZ.

#### Tipos de Exportação

| Opção                      | Descrição                                                                                                           |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| **Exportação Completa**    | Exporta todos os registros ativos cadastrados na Tabela de Temporalidade.                                           |
| **Exportação Hierárquica** | Permite exportar uma parte específica da estrutura classificatória, considerando os níveis hierárquicos vinculados. |

#### Exportação Hierárquica

Ao selecionar a opção **Exportação Hierárquica**, serão exibidos os campos:

* **Classe** (obrigatório)
* **Subclasse** (opcional)

Quando apenas a Classe for informada, o sistema exportará automaticamente todos os níveis hierárquicos vinculados, incluindo:

* Classe;
* Subclasse;
* Grupo;
* Subgrupo;
* Classificações associadas.

Caso uma Subclasse seja informada, a exportação considerará apenas os registros pertencentes ao intervalo hierárquico selecionado.

{% hint style="info" %}
**Observações**

* Apenas registros ativos são considerados na exportação.
* A estrutura hierárquica cadastrada no sistema é preservada no arquivo gerado.
* Caso a Classe selecionada não possua níveis inferiores vinculados, somente os registros daquele nível serão exportados.
{% endhint %}

### Reclassificação Automática de Documentos

A funcionalidade de **Reclassificação Automática de Documentos** permite aplicar automaticamente aos objetos documentais as alterações realizadas em códigos da Tabela de Temporalidade.

Quando uma classificação é alterada, o sistema pode atualizar os documentos vinculados a esse código, recalculando informações relacionadas à temporalidade e registrando todas as alterações realizadas.

O objetivo é garantir que os documentos permaneçam alinhados às regras arquivísticas vigentes, mantendo a rastreabilidade das alterações e o histórico de versões dos objetos.

<details>

<summary><strong>Como funciona?</strong></summary>

Ao [alterar um código na Tabela de Temporalidade ](tabela-de-temporalidade.md#editar-codigo)e salvar as modificações, o sistema exibirá a seguinte mensagem:

<figure><img src="../../.gitbook/assets/image (12).png" alt=""><figcaption></figcaption></figure>

O usuário poderá escolher entre:

* **Sim**: iniciar o processo de reclassificação dos objetos vinculados;
* **Não**: cancelar a operação de reclassificação.

</details>

<details>

<summary><strong>Confirmação por Token</strong></summary>

Por se tratar de uma operação que pode impactar um grande volume de documentos, a reclassificação exige uma validação adicional de segurança.

Ao confirmar a operação, o sistema:

1. Gera um token de validação;
2. Envia o token para o e-mail do usuário;
3. Exibe uma tela para informar o código recebido;
4. Inicia a reclassificação somente após a validação do token.

Caso o token seja inválido, expirado ou já tenha sido utilizado, a reclassificação não será executada.

**Processamento em Segundo Plano**

Após a validação do token, a reclassificação é executada em background, sem bloquear a navegação do usuário.

Durante esse processo, o sistema pode atualizar automaticamente informações como:

* Classificação documental;
* Fase Corrente;
* Fase Intermediária;
* Destinação Final;
* Datas calculadas de temporalidade;
* Demais informações vinculadas à classificação alterada.

</details>

<details>

<summary><strong>Controle de Versões</strong></summary>

Toda alteração realizada pela reclassificação gera automaticamente uma nova versão do objeto.

As versões podem ser consultadas na [**aba Versões**](../pesquisar/como-pesquisar-objetos/view-object/aba-versoes.md), disponível na visualização do documento.

Para cada alteração são registrados:

* Data e hora da modificação;
* Usuário responsável pela operação;
* Tipo da operação;
* Valores anteriores;
* Valores atualizados.

Esse mecanismo garante a rastreabilidade completa das alterações realizadas nos documentos.

</details>

<details>

<summary><strong>Relatório de Alterações</strong></summary>

Após a conclusão da reclassificação, o sistema envia automaticamente um relatório para o e-mail do usuário responsável pela solicitação.

O relatório apresenta:

* Identificador SOS do objeto;
* Campo alterado;
* Valor anterior;
* Novo valor.

Essas informações permitem acompanhar detalhadamente todas as alterações aplicadas durante o processo.

</details>

{% hint style="info" %}
#### Importante

A reclassificação automática não altera documentos individualmente por ação manual do usuário. O recurso foi desenvolvido para aplicar, de forma controlada e auditável, alterações de temporalidade decorrentes da atualização da Tabela de Temporalidade.
{% endhint %}
