<summary><strong>🏷️ O que é o Identificador SOS (ID SOS)?</strong></summary>

O **ID SOS** é um código único gerado pelo sistema DocZ para identificar cada objeto (caixa ou documento).

Se for do armazem G1 - G9 o padra de etiqueta tera 19 caracteres e a partir do G10 tera 20 caracteres.

**Exemplo de ID SOS:**

<figure><img src="../../../.gitbook/assets/image (433).png" alt="" width="467"><figcaption></figcaption></figure>

#### 📌 Estrutura do ID SOS:

<table><thead><tr><th width="131">Segmento</th><th>Significado</th></tr></thead><tbody><tr><td><strong>CB / CX / DC</strong></td><td>Tipo de objeto:<br>• <strong>CB</strong> – Caixa Box<br>• <strong>CX</strong> – Caixa 20kg<br>• <strong>DC</strong> – Documento</td></tr><tr><td><strong>00100</strong></td><td>Código de guarda vinculado ao projeto</td></tr><tr><td><strong>G1 / G2 / G3 / G4 / UN</strong></td><td>Unidade de armazenamento física:<br>• <strong>G1, G2, G3…</strong> – Galpões do armazenamento<br>• <strong>UN</strong> – Unidade externa, quando não há unidade atribuída</td></tr><tr><td><strong>0000001</strong></td><td>Número sequencial do objeto no projeto.</td></tr><tr><td><strong>SOS</strong></td><td>Identificação da empresa responsável pela gestão do objeto.</td></tr></tbody></table>

#### 📏 Quantidade de caracteres

* Se a unidade de armazenamento for **G1 até G9**, o ID terá **19 caracteres**.
* Se a unidade for **a partir de G10**, o ID terá **20 caracteres** (devido ao acréscimo de um dígito no galpão).

{% hint style="warning" %}
**Regras importantes**

* O **código de guarda (projeto)** não muda.
* Apenas o segmento referente à **unidade de armazenamento** pode variar (2 ou 3 caracteres).
* Cada **ID é único**, não pode ser duplicado ou alterado.
{% endhint %}

<summary><strong>📑Configuração para documentos finalizados</strong></summary>

A funcionalidade para documentos finalizados foi desenvolvida para garantir maior rastreabilidade, integridade das informações e conformidade com os requisitos da certificação SBIS.

Quando configurada no projeto, essa funcionalidade permite controlar quem pode realizar alterações em documentos finalizados e exigir o registro de justificativas para cada correção realizada.

#### Como funciona <a href="#como-funciona" id="como-funciona"></a>

O comportamento da funcionalidade é definido por parâmetros configurados no projeto.

Dependendo da configuração adotada, o sistema poderá:

* Permitir alterações apenas ao autor do documento;
* Exigir justificativa obrigatória para alterações;
* Registrar automaticamente uma nova versão do documento após cada correção;
* Preservar o histórico completo das versões anteriores.

#### Alteração somente pelo autor <a href="#alteracao-somente-pelo-autor" id="alteracao-somente-pelo-autor"></a>

Quando o parâmetro Alteração de Objetos somente pelo Autor estiver habilitado, apenas o usuário responsável pela criação do documento poderá realizar alterações em objetos que estejam em uma etapa documental previamente definida no projeto.

Caso outro usuário tente realizar uma alteração, o sistema bloqueará a operação e exibirá a mensagem:

"A alteração de Documentos somente é permitida apenas ao autor."

#### Justificativa obrigatória <a href="#justificativa-obrigatoria" id="justificativa-obrigatoria"></a>

Quando o parâmetro Exigir Justificativa ao Alterar um Objeto estiver habilitado, toda alteração realizada em documentos enquadrados na etapa documental configurada exigirá o preenchimento de uma justificativa antes da conclusão da operação.

A justificativa:

* É obrigatória;
* Possui limite de 255 caracteres;
* Fica associada ao histórico de alterações do documento.

Caso a justificativa não seja informada, a alteração não será concluída.

#### Controle de versões <a href="#controle-de-versoes" id="controle-de-versoes"></a>

Toda alteração realizada em um documento gera automaticamente uma nova versão do objeto.

A versão anterior permanece preservada no histórico, permitindo a consulta das informações anteriores sempre que necessário.

Dessa forma, o sistema mantém a rastreabilidade completa das alterações realizadas ao longo do ciclo de vida documental.

#### Configuração do projeto <a href="#configuracao-do-projeto" id="configuracao-do-projeto"></a>

Os parâmetros são configurados em: Projetos > Editar Projeto

Parâmetros disponíveis:

| Parâmetro                                             | Finalidade                                                               |
| ----------------------------------------------------- | ------------------------------------------------------------------------ |
| <p></p><p>Alteração de Objetos somente pelo Autor</p> | Restringe alterações ao usuário responsável pelo documento.              |
| Exigir Justificativa ao Alterar um Objeto             | Exige o preenchimento de justificativa antes da gravação das alterações. |

Quando habilitado o parâmetro Alteração de Objetos somente pelo Autor, deverá ser informada a etapa documental que será utilizada como referência para aplicação da regra.

<summary><strong>⛔ Inativação de Arquivos</strong> </summary>

A funcionalidade de **Inativação de Arquivos** permite invalidar arquivos já finalizados sem removê-los do sistema, preservando integralmente seu conteúdo, histórico e vínculo com o objeto documental.

Esse recurso atende aos requisitos de rastreabilidade e integridade documental, permitindo que um arquivo seja marcado como **Inativo**, mediante justificativa obrigatória, sem que ocorra sua exclusão.

**Como funciona**

A inativação pode ser realizada diretamente na aba **Arquivos** da View Object.

Ao selecionar um arquivo elegível para inativação e clicar no ícone **Inativar Arquivo**, o sistema solicitará uma justificativa para registrar a operação.

Após a confirmação:

* O arquivo recebe o status **Inativo**;
* A justificativa da inativação é armazenada;
* São registrados o usuário responsável e a data/hora da operação;
* O arquivo permanece disponível para consulta, download e exportação;
* O histórico da inativação fica disponível para auditoria.

<summary>📩 <strong>Compartilhamento de documentos</strong></summary>

O DocZ permite compartilhar documentos por meio de links seguros de acesso. Dependendo das permissões do usuário, do status de preservação do documento e das configurações do projeto, diferentes modalidades de compartilhamento podem ser disponibilizadas.

Os documentos podem ser compartilhados em três modalidades:

* Compartilhamento Padrão
* Pacote de Difusão (DIP)
* Pacote de Preservação (AIP)

{% hint style="info" %}
#### **Requisitos para Compartilhamento DIP e AIP**

Para que as opções de compartilhamento DIP e AIP sejam exibidas ao usuário, é necessário que:

* O parâmetro do projeto **Compartilhar Pacotes de Preservação** esteja habilitado;
* O documento possua a flag **Documento Preservado** ativa;
* O usuário possua as permissões adequadas para a modalidade desejada.

Caso alguma dessas condições não seja atendida, apenas o compartilhamento padrão ficará disponível.
{% endhint %}

**Tipos de Compartilhamento**

* **Compartilhamento Padrão**

Permite compartilhar documentos por meio de links seguros para visualização e download no DocZ.

Essa modalidade pode ser utilizada para documentos preservados ou não preservados e mantém o comportamento tradicional do sistema.

* **Pacote de Difusão (DIP)**

O Pacote de Difusão (DIP) é destinado à disseminação controlada de documentos preservados digitalmente.

O pacote é gerado pelo Eternal e pode conter:

* PDF/A assinado digitalmente;
* Metadados do documento;
* Hash de autenticação;
* Declaração de Integridade e Autenticidade;
* Relatório de Conformidade.

Sua finalidade é disponibilizar documentos com garantia de autenticidade e integridade para consultas institucionais e compartilhamento externo controlado.

* **Pacote de Preservação (AIP)**

O Pacote de Preservação (AIP) disponibiliza o conjunto completo de preservação digital armazenado no Eternal.

O pacote pode incluir:

* Arquivos preservados;
* Metadados de preservação;
* Cadeia de custódia digital;
* Logs de acesso;
* Trilha de auditoria;
* Manifestos de integridade;
* Relatório de conformidade.

Essa modalidade é indicada para auditorias, processos judiciais, comprovação legal e transferência de acervos entre instituições.

**Permissões Relacionadas:**

| Permissão                                 | Descrição                                                           |
| ----------------------------------------- | ------------------------------------------------------------------- |
| Compartilhar Arquivos                     | Permite realizar compartilhamentos padrão de documentos.            |
| Compartilhar Pacotes de Difusão – DIP     | Permite compartilhar documentos preservados utilizando Pacotes DIP. |
| Compartilhar Pacotes de Preservação – AIP | Permite compartilhar documentos preservados utilizando Pacotes AIP. |
